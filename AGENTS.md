# For coding agents

This repository is a portable **agentic workflow toolkit**. It is not an application.

- If a user gave you this repo's URL (or path) and asked you to set up, bootstrap, or start a project with it: read [`BOOTSTRAP.md`](BOOTSTRAP.md) in full and follow it. The target is the user's project, never this repo.
- If you are working **on the toolkit itself** (the user opened a session inside this repo): `payload/` is copied verbatim into target projects, `templates/` are filled in during bootstrap, `optional/` holds opt-in modules, `install.sh` does the no-clobber copy. Keep everything stack-agnostic and project-agnostic. Changes go through a branch and a pull request (this repo wires its own `guard-git.sh`: commits on main are blocked), one commit per fix. After any change: run `install.sh` against an empty temp directory and against a directory that already has a `.claude/settings.json`, and check the output; re-run `bash tests/guard-git-matrix.sh` if you touched `guard-git.sh` (and add a case for whatever you fixed), and `bash tests/scripts-smoke.sh` if you touched `slice-clock.sh` (in `optional/time-box/`), the format hook, `gate-tests.sh`, `orchestrator-check.sh` or `reinject-after-compact.sh`; `prettier --check .`. How an agent behaves when following new wording cannot be verified here — say so in the PR instead of claiming it — except what `tests/evals/` scores: a test-only plugin whose `agents/` is a symlink to `payload/.claude/agents` (the plugin loader follows a directory link, not a file link), with `claude plugin eval` cases. If you touched `Explore.md`, run `cd tests/evals/agentic-workflow && claude plugin eval . --trust-plugin --scaffold --model sonnet --max-cost-usd 3 --no-publish --ablation none` (real model calls: about $0.20 for the suite) and paste the score; add a case when you change what an agent must do. The `context: fork` and `model:` fields of the skills and agents are read by Claude Code at session start: whether a forked skill really runs on its model is proved in a target project (the harness reports the model and the token usage of the fork), not here.
